# Decisões técnicas (ADR resumido)

| # | Data | Decisão | Motivo |
|---|---|---|---|
| 001 | 2026-11-02 | Tauri 2 + Rust em vez de Electron | Binário menor, core nativo para PTY/Git/processos, modelo de capabilities. |
| 002 | 2026-11-02 | SQLite via `rusqlite` (bundled) no Rust, não pelo plugin SQL do frontend | O frontend não recebe SQL arbitrário; repositories tipados e testáveis no core. |
| 003 | 2026-11-02 | Migrations forward-only com `PRAGMA user_version` | Simples, sem dependência extra; cada milestone acrescenta um arquivo. |
| 004 | 2026-11-02 | Layout de panes como JSON opaco por workspace | O schema da árvore evolui no frontend sem migration; validação no load (`parseLayout`). |
| 005 | 2026-11-02 | `react-resizable-panels` v4 para splits; drag-and-drop no M02 | Redimensionamento acessível pronto; DnD exige modelo de drop zones próprio. |
| 006 | 2026-11-02 | Primitivos estilo shadcn escritos à mão (Radix + cva) | Controle total sobre os tokens FORGE sem o CLI interativo do shadcn; mesma API dos componentes do shadcn. |
| 007 | 2026-11-02 | Detecção de ferramentas resolve o PATH do login shell | Apps GUI no macOS não herdam o PATH do shell; sem isso, CLIs em `~/.local`, `~/.cargo` etc. não seriam encontrados. |
| 008 | 2026-11-02 | Missões no M01 só como rascunho | Respeita a regra de não ter funcionalidade falsa: o botão grava de verdade, a execução fica para M08/M09. |
| 009 | 2026-11-02 | Tipos de pane futuros aparecem desabilitados com o milestone | Roadmap visível sem botões que não funcionam. |
| 010 | 2026-11-02 | Assets da marca via `import.meta.glob` com fallback tipográfico | O build não quebra sem os arquivos e nenhuma imagem genérica substitui a marca. |
| 011 | 2026-11-02 | Geist (fontsource, empacotada localmente) | Funciona offline e dentro da CSP (sem CDN de fontes). |
| 012 | 2026-11-02 | Sessões por workspace (`workspace_sessions`) substituem `pane_layouts` | "Múltiplas sessões" = abas independentes de layout. A migration 0002 converte cada layout existente numa sessão "Principal". |
| 013 | 2026-11-02 | DnD de panes com eventos de ponteiro | O HTML5 DnD é interceptado pelo tratamento de file-drop do Tauri/WebView2. Ponteiro funciona igual nas 3 plataformas e permite preview próprio. |
| 014 | 2026-11-02 | Minimizar guarda vizinho-âncora + lado | Restaurar devolve o pane ao lugar de onde saiu, sem guardar caminhos frágeis na árvore. |
| 015 | 2026-11-02 | Layouts salvos guardam só estrutura e tipos (sem estado) | São reutilizáveis entre workspaces. O estado (ex.: arquivo aberto) pertence à sessão. |
| 016 | 2026-11-02 | Aplicar layout substitui a sessão atual com "Desfazer" no toast | Evita diálogo de confirmação e mantém a ação reversível. |
| 017 | 2026-11-02 | `portable-pty` (wezterm) para PTY | ConPTY no Windows e openpty no Unix com a mesma API, e é amplamente usado em produção. |
| 018 | 2026-11-02 | Saída do PTY via `tauri::ipc::Channel` com texto UTF-8 decodificado no Rust | Canal ordenado por chamada (melhor que eventos globais). Decodificar no Rust evita quebrar caracteres multibyte. |
| 019 | 2026-11-02 | Terminais vivem no core, não no componente | Remontar o pane (mudar o layout, trocar de aba) só reconecta, e o processo e o histórico continuam. |
| 020 | 2026-11-02 | Coleta de terminais órfãos por referência + período de carência | Uma única regra cobre fechar sessão, trocar tipo e aplicar layout, sem espalhar "dispose" pelo código e sem matar um processo durante o "Desfazer". |
| 021 | 2026-11-02 | Terminais não persistem entre execuções do app | Reabrir shells automaticamente executaria comandos sem o usuário pedir. O pane mostra "sessão encerrada" e oferece novo terminal. |
| 022 | 2026-11-02 | Atalhos globais só com Cmd no macOS; no Windows/Linux, ignorados com o terminal em foco | Ctrl+K, Ctrl+N, Ctrl+[ etc. pertencem ao shell. |
| 023 | 2026-11-02 | `monaco-editor` direto (sem `@monaco-editor/react`) com workers do Vite | O wrapper carrega o Monaco de CDN por padrão, o que viola a CSP e o uso offline. |
| 024 | 2026-11-02 | Gravação atômica + concorrência otimista por mtime | Nunca deixa um arquivo pela metade e nunca sobrescreve em silêncio uma mudança feita por outro processo (por exemplo, um agente ou o git). |
| 025 | 2026-11-02 | Excluir = mover para a lixeira do SO | A operação continua recuperável, coerente com "confirmação para operações destrutivas". |
| 026 | 2026-11-02 | Busca com a crate `ignore` em vez do binário `rg` | Mesmo comportamento do ripgrep, sem depender de um binário externo e funcionando igual nas 3 plataformas. |
| 027 | 2026-11-02 | `node_modules/` sempre ignorado na busca e no Quick Open | Ele quase nunca é alvo de edição e domina o tempo e o volume da busca. A árvore de arquivos continua mostrando a pasta. |
| 028 | 2026-11-02 | Diagnósticos semânticos de TS desligados no Monaco | Sem o contexto do projeto, todo import apareceria como erro. A análise real virá dos agentes e das ferramentas do projeto. |
| 029 | 2026-11-02 | Atalhos globais na fase de captura | O app vence widgets que consomem teclas (o Monaco usa ⌘K como prefixo de acordes). `⌘[`/`⌘]` continuam com o editor. |
| 030 | 2026-11-03 | Git via binário do usuário (não libgit2) | Usa exatamente a configuração, os hooks, o credential helper, o SSH e as filtragens do usuário. Comportamento idêntico ao terminal. |
| 031 | 2026-11-03 | Stage de linhas reescrevendo o blob do índice (`hash-object` + `update-index`) | É mais robusto que gerar patches para `git apply --cached`, sem problemas de contexto ou espaços. A granularidade é o bloco de alteração do diff do Monaco. |
| 032 | 2026-11-03 | Pull só `--ff-only` e push nunca forçado | Evita merges surpresa e reescrita de histórico remoto. Casos divergentes aparecem como erro para o usuário decidir. |
| 033 | 2026-11-03 | Worktrees numa pasta gerenciada do app | Não polui o repositório nem a pasta do usuário, e o FORGE sabe quais pode criar e limpar. |
| 034 | 2026-11-03 | Atualização do status por eventos + polling leve (10 s, só com a janela visível) | Sem watcher de filesystem por enquanto: é simples, previsível e barato. |
| 035 | 2026-11-03 | Agentes interativos = o CLI oficial rodando no PTY | Usa a UI, os recursos, a autenticação e a cobrança nativos de cada CLI. Nada é reimplementado nem intermediado. |
| 036 | 2026-11-03 | Estado de login por comando de status ou presença de arquivos, nunca por leitura de credenciais | Satisfaz "não exigir que o usuário pague de novo" sem que o FORGE toque em tokens. |
| 037 | 2026-11-03 | "Verificado" só após teste real na versão instalada, com confirmação explícita (consome tokens) | Atende "não prometer suporte antes de implementar e testar" e evita gasto silencioso. |
| 038 | 2026-11-03 | Ambiente do login shell interativo passado aos agentes, só em memória | Chaves e configurações do `.zshrc` funcionam como no terminal do usuário, e nada é persistido. |
| 039 | 2026-11-03 | Fixtures de teste a partir de saídas reais higienizadas | Os parsers são validados contra o formato verdadeiro de cada CLI. O caminho de sucesso de Codex e Gemini usa o formato documentado até o primeiro teste real. |
| 040 | 2026-11-03 | Execuções de agente = CLI oficial em modo sem interface com saída estruturada, normalizada para um modelo de eventos comum | Uma única UI e um único histórico para os três providers, mantendo autenticação e recursos nativos. |
| 041 | 2026-11-03 | Permissões em 3 níveis mapeadas para os modos nativos de cada CLI, com "somente leitura" como padrão | Menor privilégio por padrão. "Acesso total" exige confirmação a cada execução. |
| 042 | 2026-11-03 | Cada execução roda em seu próprio grupo de processos | Cancelar ou estourar o timeout encerra também os subprocessos (comandos que o agente iniciou). |
| 043 | 2026-11-03 | Eventos persistidos com segredos mascarados e limites de tamanho. Deltas de texto só ao vivo | Atende "nunca registrar secrets nos logs" e evita inflar o banco com milhares de fragmentos. |
| 044 | 2026-11-03 | Worktree opcional por conversa (`forge/agent-<id>`) | Agentes que editam podem trabalhar isolados, sem tocar no diretório do usuário. A integração é feita depois pelo Git Center. |
| 045 | 2026-11-03 | Continuar conversa = retomar a sessão nativa (`--resume` / `exec resume`). Gemini sem continuação | O Gemini só retoma por índice ou "latest", o que não identifica a conversa com segurança. |
| 046 | 2026-11-03 | Runner usa conexão SQLite própria (WAL) por execução | As threads de streaming persistem sem disputar o lock da conexão principal. |
| 047 | 2026-11-03 | Gemini roda com `--skip-trust` (confiança só para a sessão) | Sem isso, o CLI rebaixa silenciosamente o modo de aprovação em pastas não confiáveis, e a permissão escolhida no FORGE não seria respeitada. |
| 048 | 2026-11-03 | Plano gerado por agente em JSON entre marcadores `<forge-plan>`, validado (chaves, perfis, dependências, sem ciclos) antes de virar tarefas | A saída do LLM nunca é confiada sem validação, e o usuário revisa e edita o plano antes de iniciar. |
| 049 | 2026-11-03 | Uma worktree por tarefa, partindo da branch da 1ª dependência e com merge das demais | Tarefas paralelas nunca editam o mesmo checkout, e cada tarefa já enxerga o trabalho das que a precedem (atende a regra do Maestro). |
| 050 | 2026-11-03 | Commit automático do resultado da tarefa na branch dela, respeitando os hooks do usuário | A revisão e a integração trabalham com commits reais. Se um hook falhar, a tarefa falha com a mensagem dele, em vez de ser contornado. |
| 051 | 2026-11-03 | Integração explícita: merge das branches aprovadas na branch base, só com o workspace limpo, idempotente e parando no 1º conflito | Nada entra na branch do usuário sem uma ação dele. Conflitos são resolvidos no Git Center e a integração é retomada. |
| 052 | 2026-11-03 | Revisão por tarefa ligada por padrão (configurável), com paralelismo de 1 a 4 | Pontos de aprovação claros no M08. Autonomia maior fica para os modos do Maestro (M09). |
| 053 | 2026-11-03 | Motor com lock único e callbacks de término do runner, notificando a UI via evento `forge://mission-changed` | Transições de estado serializadas (sem lançar a mesma tarefa duas vezes) e UI atualizada sem polling. |
| 054 | 2026-11-03 | Custo da missão = soma só dos valores informados, com a contagem de execuções que informaram | Distingue o dado real da ausência de dado, sem estimar. |
| 055 | 2026-11-03 | Três modos no Maestro: Free (humano decide), Squad (agente revisor recomenda, humano decide) e Agentic (Maestro decide dentro de limites) | Autonomia configurável por missão. Aprovar o plano e integrar na branch continuam sendo sempre gates humanos. |
| 056 | 2026-11-03 | Revisão automática pelo perfil Code Reviewer, em somente leitura, na worktree da tarefa, com veredito JSON entre `<forge-review>` | Revisão independente de quem implementou, contra os critérios de aceite. O veredito é validado (o último bloco vale, porque o prompt ecoa o formato). |
| 057 | 2026-11-03 | Política de falha no Agentic: refazer até N tentativas, depois reatribuir 1 vez a outro provider instalado e logado, depois escalar para o humano | Tratamento de falhas e reatribuição sem loops infinitos. A sondagem de providers só ocorre quando necessária. |
| 058 | 2026-11-03 | Limites por missão (execuções e orçamento pelos custos informados) que pausam a missão | Evita execução descontrolada. O orçamento é honesto: só conta valores reportados pelos CLIs. |
| 059 | 2026-11-03 | Relatório final determinístico (sem LLM), gerado antes de marcar a missão como concluída | Contém só fatos registrados (tarefas, commits, revisões, tokens e custos informados) e nunca fica ausente numa missão concluída. |
| 060 | 2026-11-03 | Ordem "registrar evento/artefato → mudar status" nas transições observáveis | Quem lê o status (UI ou testes) sempre encontra o motivo e o relatório. Isso eliminou condições de corrida encontradas nos testes. |
| 061 | 2026-11-03 | Squad = perfis com função, etapa (ordem no fluxo) e regras. O planejador vem do próprio squad e só pode atribuir tarefas a membros | O squad realmente condiciona a orquestração, em vez de ser um rótulo. Papéis fora do squad caem num membro. |
| 062 | 2026-11-03 | Papéis da especificação que não existiam viraram perfis padrão (PM, Creative Director, Copywriter, Game Designer, Artist, Planner, Researcher, Executor) | Os 5 squads da especificação ficam completos e editáveis como qualquer perfil. |
| 063 | 2026-11-03 | Receita = briefing com `{{campos}}` declarados + squad + modo e limites do Maestro + plano opcional | Placeholders não declarados são rejeitados na validação. Campos opcionais vazios viram "não especificado" (nunca ficam `{{x}}` no prompt). |
| 064 | 2026-11-03 | "Salvar como receita" a partir de uma missão (escapando `{{ }}` do texto) | É a forma natural de criar planos prontos reaproveitáveis, sem um editor de plano duplicado. |

| 066 | 2026-11-03 | Diálogos de arquivo para exportar e importar abertos pelo Rust, não pelo frontend | O caminho gravado ou lido vem sempre de uma escolha explícita do usuário, e o frontend não ganha permissão genérica de escrita em disco. |

| 073 | 2026-11-03 | Instalação em duas etapas por token (o Rust lê a pasta escolhida no diálogo nativo e o frontend só confirma) e heurísticas de risco na prévia | O conteúdo instalado é exatamente o que o usuário revisou.
